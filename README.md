# Nika Business: интернет-магазин на GitHub Pages

Статический интернет-магазин без своего сервера. Товары, баннеры, название, логотип и цвета настраиваются в админке. После оформления заказа покупателю приходит письмо-подтверждение через EmailJS. Один и тот же код подходит для любого магазина: всё, что отличает магазины, хранится в `site.json` и `products.json`.

- Сайт: https://jabamentsos71.github.io/nika-business/
- Репозиторий: https://github.com/JabaMentsos71/nika-business
- EmailJS: сервис `service_eqi984h` (Gmail), шаблон `template_ktrn6fd`. Копия каждого заказа приходит владельцу через Bcc.
- Админка: https://jabamentsos71.github.io/nika-business/admin.html

## Витрина (index.html)

- Слайдер баннеров: смена каждые 6 секунд, стрелки, точки, свайп на телефоне. Кнопка баннера может вести в каталог, в категорию, на конкретный товар или на другой сайт.
- Компактные карточки: на компьютере 4 в ряд, на телефоне 2. В карточке фото, метка («Хит», «Новинка»), скидка в процентах, 2 строки описания, 2 ключевых пункта, цена с единицей («/ мес») и зачёркнутой старой ценой.
- «В корзину» добавляет товар без открытия корзины, а кнопка превращается в счётчик «− 2 +».
- Окно «Подробнее» по клику на фото или название: полное описание, все пункты, цена. У каждого товара есть своя ссылка вида `…/#product=p-audit`.
- Фильтр по категориям, поиск, сортировка (дешевле, дороже, со скидкой, по названию).
- Корзина сохраняется в браузере. «Итого» и кнопка оформления всегда видны внизу экрана.

## Админка (admin.html)

Три вкладки:
- **Товары** — добавить, изменить, скопировать, скрыть, удалить (с отменой), менять порядок, поиск и фильтр.
- **Баннеры** — картинка, заголовок, текст, кнопка и куда она ведёт, светлый или тёмный текст, порядок, скрытие.
- **Оформление** — название, логотип, описание для поисковиков, цвета (плюс готовые сочетания), валюта, главный экран, заголовки каталога, контакты и соцсети, текст подвала, ключи EmailJS. Справа живое превью. Там же: скачать резервную копию магазина в файл, загрузить её обратно и инструкция «как сделать ещё один магазин на этом шаблоне».

Фото везде можно перетащить, выбрать файлом, вставить Ctrl+V или дать ссылку. По ссылке админка сама скачает картинку и сохранит её в репозиторий. Фото уменьшаются (товары до 1200 px, баннеры до 1800 px, логотип до 400 px) и сжимаются в WebP.

Репозиторий админка определяет по адресу сайта (`https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/admin.html`), поэтому в копии шаблона ничего в коде менять не нужно.

**Первый вход.** Нужен токен GitHub (один раз):
1. https://github.com/settings/personal-access-tokens/new
2. Token name: «Nika admin», Expiration: 90 дней.
3. Repository access → Only select repositories → `nika-business`.
4. Permissions → Repository permissions → Contents → **Read and write**.
5. Generate token → скопировать → вставить в админке.

Токен хранится только в браузере, где вы вошли, и даёт доступ только к этому репозиторию.

**Публикация.** Правки копятся в черновике (он переживает перезагрузку страницы). Кнопка «Опубликовать» отправляет всё одним коммитом: новые фото, изменившиеся `products.json` и `site.json` и удаление ненужных фото. Затем GitHub Pages пересобирает сайт (обычно до 1–2 минут), и админка сама показывает «Изменения уже на сайте». Если магазин за это время изменили в другой вкладке, админка спросит, что делать, и не перезапишет чужие правки молча.

**Демо-режим** — кнопка на экране входа: можно всё попробовать без токена, но сохранить нельзя.

## Если письмо «не пришло»

Сначала откройте EmailJS → Email History. Если там есть запрос со статусом **OK**, значит, сайт и EmailJS отработали, а Gmail отправил письмо. Дальше всё решает почта получателя: попросите его проверить «Спам», «Промоакции» и поиск по «Nika Business». Если запроса в истории нет, значит, заказ не дошёл до EmailJS: на сайте была красная ошибка, браузер открыл старую версию страницы или сработал блокировщик рекламы.

## Как это устроено

GitHub Pages только отдаёт файлы (HTML, CSS, JS). Своего сервера, который мог бы отправить письмо, у него нет. Поэтому письмо отправляет посредник:

```
Браузер покупателя                 EmailJS (их сервер)            Gmail (ваш ящик)        Почта покупателя
  index.html  ── emailjs.send() ──▶  берёт шаблон письма,  ──SMTP──▶  отправляет письмо ──▶  "Заказ NB-123456 принят"
  (данные формы в JSON)              подставляет {{данные}}
```

1. Покупатель заполняет форму и нажимает «Оплатить».
2. JavaScript (`buildOrderParams()`) собирает данные в объект: имя, email, товары, сумму.
3. `emailjs.send(SERVICE_ID, TEMPLATE_ID, params)` отправляет этот объект HTTPS-запросом на сервер EmailJS вместе с вашим Public Key.
4. EmailJS по `TEMPLATE_ID` находит шаблон и подставляет значения вместо `{{customer_name}}`, `{{order_total}}` и т.д.
5. По `SERVICE_ID` EmailJS понимает, через какой ящик отправлять (ваш подключённый Gmail), и отправляет письмо на адрес из поля **To Email** шаблона, то есть на `{{customer_email}}`.
6. Сайт получает ответ `200 OK` и показывает экран «Заказ оформлен». При ошибке под суммой появляется красное сообщение.

**Почему EmailJS, а не Formspree.** Formspree пересылает заявки **владельцу сайта**. Отправить письмо покупателю на его адрес на бесплатном тарифе он не может. В EmailJS адрес получателя задаётся переменной, поэтому письмо приходит тому, кто сделал заказ.

**Безопасно ли держать ключ в коде.** Public Key специально сделан публичным. Злоупотребления ограничиваются настройками в кабинете EmailJS (список разрешённых доменов, лимиты). Private Key в код сайта не вставляйте никогда.

## Шаг 1. Опубликовать сайт на GitHub Pages

1. Зайдите на https://github.com, нажмите **New repository**.
2. Имя, например, `nika-business`. Выберите **Public** и нажмите **Create repository**.
3. На странице репозитория нажмите **uploading an existing file** и перетащите `index.html` (и при желании `README.md`). Нажмите **Commit changes**.
4. Откройте **Settings → Pages**.
   - Source: **Deploy from a branch**
   - Branch: **main**, папка **/ (root)**, затем **Save**.
5. Подождите 1–2 минуты и обновите страницу. Появится ссылка вида
   `https://ВАШ_ЛОГИН.github.io/nika-business/`.
6. Откройте её. Сайт должен работать (корзина, форма). При отправке формы пока будет сообщение «EmailJS ещё не настроен». Так и должно быть.

## Шаг 2. Настроить EmailJS

1. Зарегистрируйтесь на https://www.emailjs.com (бесплатно 200 писем в месяц).
2. **Email Services → Add New Service → Gmail → Connect Account.** Войдите в Gmail, с которого будут уходить письма, и разрешите отправку.
   Нажмите **Create Service**. Скопируйте **Service ID** (например `service_ab12cd3`).
3. **Email Templates → Create New Template.**
   - **Subject:** `Заказ {{order_number}} принят — Nika Business`
   - **Content:** нажмите *Edit Content → Code Editor* и вставьте содержимое `emailjs-template.html`.
   - Справа, в блоке настроек получателя:
     - **To Email:** `{{customer_email}}` ← это самое важное: письмо уйдёт покупателю
     - **From Name:** `Nika Business`
     - **Reply To:** ваш email (чтобы покупатель мог ответить)
     - **Bcc:** ваш email, если хотите получать копию каждого заказа
   - **Save.** Скопируйте **Template ID** (например `template_xy98zw7`).
4. **Account → General**: скопируйте **Public Key**.
5. (Рекомендуется) **Account → Security**: в списке разрешённых доменов (allowed origins) укажите `https://ВАШ_ЛОГИН.github.io`. Тогда никто не сможет использовать ваш ключ с другого сайта.

## Шаг 3. Вписать ключи в сайт

В `index.html` найдите блок (в начале `<script>`):

```js
const EMAILJS_CONFIG = {
    PUBLIC_KEY:  'ВАШ_PUBLIC_KEY',
    SERVICE_ID:  'ВАШ_SERVICE_ID',
    TEMPLATE_ID: 'ВАШ_TEMPLATE_ID'
};
```

Замените три значения на свои и сохраните файл. Затем загрузите обновлённый `index.html` в репозиторий (**Add file → Upload files**, подтвердите замену). Через минуту GitHub Pages обновит сайт.

## Шаг 4. Проверить

1. Откройте сайт по ссылке GitHub Pages (нажмите Ctrl+F5, чтобы не открылась старая версия из кэша).
2. Добавьте услугу в корзину, нажмите **Перейти к оформлению**, укажите **свой** email и нажмите **Оплатить**.
3. Должен появиться экран «Заказ оформлен», а через несколько секунд письмо на почте. Если его нет во входящих, проверьте **Спам**.
4. В кабинете EmailJS, в разделе **Email History**, видно каждую отправку и её статус.

## Если не работает

Откройте консоль браузера (**F12 → Console**) и нажмите «Оплатить» ещё раз. Там будет строка `EmailJS: ошибка отправки` с кодом и текстом ошибки.

| Ошибка | Причина |
|---|---|
| `400 The Public Key is invalid` | Неверный или пустой `PUBLIC_KEY`. |
| `400 The service ID is invalid` / `template ID not found` | Опечатка в ID, либо шаблон не сохранён. |
| `422 The recipients address is empty` | В шаблоне поле **To Email** не заполнено `{{customer_email}}`. |
| `403 ... not allowed` | Домен сайта не добавлен в Account → Security. |
| `412 Gmail_API: Invalid grant` | Слетело подключение Gmail. Переподключите сервис в Email Services. |
| `emailjs is not defined` | Не загрузился скрипт EmailJS: проверьте интернет и блокировщик рекламы. |
| Письмо в Email History есть, во входящих нет | Посмотрите папку «Спам». |

Если надо обратиться за помощью, пришлите: ссылку на репозиторий, ссылку на сайт и текст ошибки из консоли.
